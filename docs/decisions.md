# Design decisions

Answers to the open questions in the project handoff, settled Oct 18, 2026.

| Question | Decision |
| --- | --- |
| Host OS | Linux (Ubuntu 26.04). Explicit proxy first; transparent mode optional. |
| CPU or GPU | CPU only. The host GPU is an AMD RX 580 (no CUDA, no current ROCm support). |
| Censor style | Gaussian blur by default; `censor.style` is configurable (`gaussian`, `pixelate`, `solid`). |
| Fail open or closed | Fail closed: if detection errors or times out, blur the whole image and deliver it. |
| Scope of "explicit" | Exposed anatomy only (`*_EXPOSED` labels). No InsightFace fallback in v1. |
| Female-only selection | Censor an explicit allowlist of labels (`FEMALE_BREAST_EXPOSED`, `FEMALE_GENITALIA_EXPOSED`) rather than matching a `FEMALE_` prefix. Unsexed labels (`BUTTOCKS_EXPOSED`, `ANUS_EXPOSED`) are censored unless they sit near male context and not near female context (`FEMALE_*`, `FACE_FEMALE`); with no attribution either way they are censored. Never the whole image. |
| Context thresholds | Female labels use 0.5 by default; 0.35 when the box touches another confident female box (the missed second breast in `made-to-be-thrown-around`); 0.65 when nothing else in the image is female but male context is present (the male chest misread as female in `rub-an-irish…`). Both configurable. Tuned on 15 samples, so expect to revisit. |
| Model | 320n for now, for speed (~0.25 s vs ~2 s per image with tiling). 640m stays baked into the image as a config switch. On the 15 samples 640m gets every image right; 320n misses `mixed/daddy-said` (reads exposed breasts as covered) and `mixed/what-kinda-cage` (its one breast score overlaps the `rub-an-irish` false positive). Both are recorded as known failures in the 320n fixture. |
| Unsexed attribution tweaks | A female detection overlapping an unsexed box counts from 0.25 and overrides the male exemption (`mixed/cum-covered-back`: a woman's buttocks next to a male detection). Context detections count from 0.35, not 0.4 (fixes `uncensor/completely-helpless` under 320n; no change under 640m). |
| Male vs female score per box | The detector keeps every class's score per box (NudeNet's own postprocessing keeps only the best), so a female box's male-counterpart score is visible in `draw_boxes.py` output and the debug log. `male_score_ratio` can pass a female box the model also scores male, but is off (0): on the 45 samples (Oct 18, 2026) the model scores classes independently, and the male chest misread as female in `rub-an-irish` scored male 0.000 under both models, the same as real female breasts (0.000-0.014). Kept for trying on more data. |
| Penises over breasts | A `FEMALE_BREAST_EXPOSED` box that overlaps a `MALE_GENITALIA_EXPOSED` box scoring 0.35+ by half or more of the smaller box passes, so the blur never lands on a penis (and a penis read as a breast, box inside box, isn't blurred); it doesn't corroborate other breasts either. Edge contact (under 0.25 in browsing logs, typical of real breasts next to a penis) stays censored; the 0.35 floor keeps the weak penis detections (0.26, 0.28) in two `censor/` samples from uncovering real breasts. Keys: `yields_to_male`, `male_priority_labels`, `male_priority_threshold`, `male_priority_overlap`. No sample changed under either model. |
| Video sex attribution | A male subject whose chest both models read as female (viewkey `6710b29dca308`, Oct 18, 2026: breasts median 0.44, max 0.76, in half the samples) can't be fixed per frame: a penis or male face shares the frame with only ~5% (320n) / ~35% (640m) of those breast boxes, and 320n reads the face as female more often than male. `video_attribution` decides over time instead: a second decode at 1 fps runs 640m (which sees the penis in every 20 s of that video, where 320n goes 100 s without) ahead of the job, and a moment is a male stretch when the window 30 s before to 10 s after it has 3+ frames with a penis or male face at 0.35+ and none with a female face or female genitalia at 0.35+. There, `FEMALE_BREAST_EXPOSED` is neither censored nor female context; female genitalia stay censored. The lookahead means a woman coming into frame is seen before her frames are written, and the start of a video needs no history; it costs ~7 s more before playback (ready at ~8.5 s instead of ~1.5 s) and a second fetch of the stream, and jobs run at 1.4x real time instead of 3.9x. Any scan failure or stall censors as before. Replayed on that video: censored samples 813 to 188 at a 0.35 female threshold (two 40 s stretches vetoed by 3 weak female frames), to 12 (the genitalia) at 0.45. **Off by default**: not yet measured on straight videos, where a woman's breasts with a penis in frame must stay censored. Tune with `tools/dump_video_scores.py` and `tools/replay_attribution.py`. |
| Data URIs | One bytes-level regex over HTML, CSS and JSON bodies instead of selectolax parsing (dropped from the image): it covers `src`, `srcset`, inline styles, CSS `url()` and JSON strings, including JSON's `\/` escaping. Each image gets the per-image timeout; failures fail that image closed. |
| Mislabelled and embedded images | Ads were getting through (Oct 18, 2026), so images are found by their bytes, not only by `Content-Type: image/*`: anything requested with `Sec-Fetch-Dest: image`, and `application/octet-stream`-style or missing types up to `images.sniff_max_bytes`, are checked for a JPEG/PNG/GIF/WebP/AVIF signature. Browsers render such images whatever the label says. Data URIs are also scanned in JavaScript, XML, SVG, `+json`/`+xml` and plain text bodies (ad tags carry creatives in script), with parameters before `;base64` and any letter case, and base64 SVG data URIs are decoded to reach the images inside (`data_uris.svg_depth`). A script or stylesheet pinned with Subresource Integrity stops loading if one of its images is censored: accepted, as failing closed. At `debug`, image requests that weren't scanned are logged as `unscanned` with the reason. |
| Recall over precision | False positives are preferred to misses, but breasts at 0.3 over-triggered, so they sit at the midpoint of what was tested. Default threshold 0.3 (genitalia, buttocks); `FEMALE_BREAST_EXPOSED` 0.4; second-of-a-pair 0.3; lone female box with male context 0.625. Tall or wide images are also scanned as overlapping square tiles (`model.tiling`), which recovers small regions lost when a 1080x1900 phone photo is shrunk to the model input. On 44 samples: 320n 36 right (6 misses, 2 male false positives) at ~0.25 s/image median; 640m 40 right (4 misses, no false positives) at ~2 s/image. Long animations scan at most 48 frames. |
| Video scope | Video control injected on every site, not an allowlist: much of the content is embedded from other hosts. The cost is that every page's CSP is extended for our script and any page can ask the proxy to fetch a public video URL; a user-facing warning about this is still to come. Private and loopback sources stay refused. |
| Page-facing surface | Every page can reach `censor.local`, so it gives away as little as it can and takes as little as it can (Oct 19, 2026). `/health` and `/inject.js` send no CORS headers, so a page can't fetch them to tell the proxy is running; the job endpoints echo the `Origin` only when it matches `video.hosts`. The script keeps no named global (a non-enumerable symbol on `document` guards against running twice) and removes its own `<script>` tag once it has run; the patched `fetch`/`play`/`attachShadow` prototypes and the card elements stay detectable, which can't be helped. The `Referer` ffmpeg sends comes from the browser-set `Origin` header (`https://host/`, what browsers send cross-origin by default), never from the page-supplied URL, which is kept only for the admin panel. Job starts are capped: `video.max_queued_jobs` (8) waiting at once, `video.max_starts_per_minute` (12) per origin; refusals answer 429 and the card shows the reason. ffmpeg runs with `-protocol_whitelist` from `video.source_protocols` (https, http, tls, tcp, crypto), so an HLS playlist can't point it at `file:`, `concat:` or `data:`; the container mounts the CA key, so this matters. Job ids are random and jobs are keyed by (page origin, source URL), not by source alone (Oct 19, 2026): an id derived from the URL let any page that knows a video URL poll the status of a job another site started, and a shared cache hit told it the same; the cost is that a video embedded on two sites is processed twice. The debug beacon takes posts only from allowlisted origins. DNS rebinding and redirects to private addresses after `check_source` remain possible. |
| Injection point | The tag goes right after `<head>`, else `<html>`, else the doctype, but only before the page's first `<body>` or `<script>` (Oct 19, 2026): a page with no head element whose script holds a reflected `<head>` string would otherwise get our tag inside that string, where its `</script>` ends the script and turns what follows into live HTML. Pages with nothing usable before their first script are left alone. There is no "already injected" body check: it let any site opt out of the video control by including the marker string. The proxy injects each response once, and the script runs once per document on its own. The compose service runs with a read-only root (tmpfs on `/tmp` for the video cache), no capabilities and `no-new-privileges`; the CA directory stays writable because mitmproxy creates the CA there on first start (append `:ro` afterwards). The service runs as an unprivileged user (`user:` in `compose.yaml`, 1000:1000 to match the host account; files the root container wrote appear as that uid under Docker Desktop anyway), with the confdir moved from `/root/.mitmproxy` to `/mitmproxy` so the mount is reachable without root. |
| Streaming and oversized images | mitmproxy's `stream_large_bodies` is not used: it is applied after the addon's hook and was streaming every image over 5 MB past the censor (found Oct 18, 2026 via a 74 MB Reddit GIF). The addon buffers images and scanned text and streams everything else. Images over `images.max_bytes` (256 MB) or `max_decoded_bytes` (2 GB decoded), or with too many frames, fail closed as their first frame fully censored. |
| Pre-filter | OpenNSFW2 dropped (it pulls in TensorFlow). NudeNet runs on every image above the size floor; repeat images are served from a content-hash cache. |
| Log contents | Hostnames by default. Full URLs are logged only at the more verbose level. Configurable. |
| Browsers | Firefox and Chromium (both snaps). Chromium trusts the CA through the `CACertificates` policy in `/var/snap/chromium/current/policies/managed/`; its updater hosts are passed through. Verified with a test profile on live HTTPS (Reddit images censored in 76-294 ms with 320n). Still to do: system-wide proxy via the PAC file, and Firefox. |
| Fail-open when container is down | Use a PAC file (`PROXY localhost:8080; DIRECT`) rather than relying on a health check. |
| Test fixtures | Run `tools/draw_boxes.py` on `docs/samples/`, have the boxes confirmed by eye, then freeze them per model (`src/tests/fixtures/expected-<model>.json`). Folder names are ground truth: `censor/` and `mixed/` must be censored, `uncensor/` clean. A model's known failures stay in its fixture as strict xfails with the correct result. Samples are not in git. |
| Video source fetching | ffmpeg's requests are made to look like a browser's, because CDNs reject anything else (Pornhub's answers 410 when `User-Agent` comes before `Host` or when an HLS request carries `Range: bytes=0-`; found Oct 18, 2026). Players that fetch their manifest only on play are handled by reading manifest URLs from the page's inline scripts, generically rather than per site. With one job at a time, an abandoned 17-minute video was blocking the next one, so pages cancel their jobs when they close or move on, a job paused or in a background tab for `video.idle_seconds` (5) yields to a video someone is waiting on, and jobs nobody asks about for `video.abandon_seconds` (5) are cancelled. Pausing alone never stops a job. |
| Image placeholders | Images queue for the censor's workers, leaving blank boxes on image-heavy pages (Oct 18, 2026), so the injected script covers an image still loading `images.placeholder_delay_ms` (400) after it comes into view with a branded card, removed on load or error. Decided in the page, not the proxy: the browser already knows which images are unfinished, and asking the proxy which URLs are queued would mean polling and would let any page see what other tabs are loading. The cost is that a slow network also shows the card. The cards stack at the image's own z-index (a sticky header still covers them), are clipped by hand to the image's scrolling ancestors, and let clicks through. The script is now injected while either video or placeholders are on. Images the page leaves unsized (pasted GIFs; in the log animated GIFs take 10-20 s, several timing out) take no room while loading, so the card covers a sized box the image sits alone in, or else the image is held open at `images.placeholder_reserve_px` (160) on its unsized axes until it loads; images sized by attribute or inline style, such as tracking pixels, are left alone. CSS background images and images opened in their own tab get no placeholder. |
| Queue bypass | Images that need no detection (below the size floor or `min_side_px`, not a supported image, or a cache hit) were waiting for a detection worker like any other, so icons, tracking pixels and repeat images queued behind 10-20 s animated GIFs, and so did whole HTML/JS bodies whose only data URIs were tiny placeholders. `Censor.precheck()` now settles those from the header and hash alone, on asyncio's default thread pool, before anything is queued; only images that need the model take a worker. |
| Branding | Sissy Censor System: plum ground (#16121A), petal pink accent (#FF6FAE, #C8337A on light grounds), and a 3x3 mosaic mark (a pixelate censor softened into a blurred spot). Bricolage Grotesque and IBM Plex Mono, used only if installed locally: the overlay uses system fonts rather than fetch them. Overlay buttons are dark text on pink (white on pink fails contrast); retry is a secondary outline button. See `docs/brand/`. |
| Admin panel | Its own listener (`admin.port`, 8082), published on the host's loopback (`http://localhost:8082/admin`), with the proxy routing `proxy.admin_host` (`scs.local`) to it. `censor.local` stays the address for the injected script and video jobs. It is not on the internal server because that one is open to every page (CORS `*`) and bound to the container's loopback. Every page can reach both panel addresses, so it checks `Host` (DNS rebinding), takes writes only as JSON with its own `Origin`, and sends no CORS headers. There's no password by default. An optional PIN (PBKDF2-hashed in `config.yaml`) locks the whole panel. Wrong entries never lock anyone out (the slow, serialised PBKDF2 check paces guessing). Instead they're recorded in `admin.attempts_log`, a file so a restart doesn't hide them, and reported after the next unlock until dismissed. The panel gives no hint on resetting the PIN; deleting `admin.pin_hash` does it. Settings are written to `config.yaml` with ruamel.yaml, which keeps comments, and are applied live: the censor is rebuilt (keeping the loaded model when `model` is unchanged) and swapped on the event loop. Ports, the video cache directory and job slots still need a restart. |
| Censoring levels | `detection.preset` picks a named bundle of detection settings from `detection.presets`, or `custom`. Strict is the defaults as they stand, so tuning the defaults moves strict with it. Lax removes `FEMALE_BREAST_EXPOSED` from `female_labels` but keeps it in `female_context_labels`, so buttocks next to exposed breasts are still censored. There is no limit on the number of presets: `config.yaml` presets merge with the built-in ones by name (null removes one), and the panel lists them all. Under a preset, detection keys in `config.yaml` are kept but ignored, and the panel refuses to set them. Each level's card lists what it censors, worked out from its `female_labels` and `unsexed_labels` ("Exposed breasts"), so the list can't drift from the settings; the description holds only what the list can't say. The panel shows individual settings only in custom. Switching to custom with no custom keys saved writes the previous preset's settings first, so behaviour doesn't change until you edit. Tests that tune detection through config set `preset: custom`. |
| Model picker | The models baked into the image are listed in `model.available` (name, label, path, resolution). The panel's top-level Fast/Slow switch picks the image model from their labels, and a dropdown offers them as one choice for `model.path`+`resolution` and for `video.model_path`+`model_resolution`, so the two can't be mismatched. |
| Whitelist | One whitelist (Oct 18, 2026; it replaced a scan-only domain whitelist and a separate passthrough list): whitelisted hosts go to mitmproxy's `ignore_hosts`, so they are never decrypted, the proxy never sees their logins or money, and nothing from them is censored. `whitelist.builtin` ships regexes on `host:port` for Chromium updaters (they break under interception), operating system and firmware updates (Ubuntu, Snap, Flathub, fwupd, Debian, Fedora, Windows, Apple), Docker (`docker.io` and `docker.com`: the Hub registry, image layers, Docker Desktop and its sign-in; added Oct 19, 2026, because pulls fail under interception and carry Hub credentials), sign-in providers, password managers, payment processors, banks, brokerages and credit bureaus (US, UK, Australia, Canada), health portals (MyChart on any `mychart.` host), insurers, pharmacies, labs and HSAs, streaming services and their video CDNs (Netflix, Disney+, Hulu, Max, Prime Video, Paramount+, Peacock, Crunchyroll, HIDIVE, Apple TV+, Tubi, Pluto TV, and YouTube with its `ytimg.com` thumbnails and `googlevideo.com` video; their DRM video can't be censored, so the video control would only keep their players covered, and their artwork passes uncensored by choice), and every `.gov`, `.mil`, `.edu`, `gov.uk` and `edu.au` host. User entries are plain domains in `whitelist.domains` (subdomains included, leading `www.` dropped), added to the built-in list, because config lists replace wholesale. A whitelisted host is a hole in the censor, so only hosts that don't serve explicit content qualify: not google.com or gstatic.com (Image Search thumbnails), CDNs, social or chat sites. Whole `.gov`, `.mil`, `.edu`, `gov.uk` and `edu.au` are passed by choice: their galleries, medical images and personal pages aren't the explicit content the proxy is for. Requests whose `Referer`/`Origin` is a whitelisted page pass unscanned too (`whitelist.match_referer`, on), because sites load their images from other hosts (`youtube.com` from `i.ytimg.com`); the cost is that ads and third-party images on a whitelisted page pass as well. At `debug`, those are logged as `unscanned` with reason `whitelisted (<domain or pattern>)`. Electron apps fail TLS through the proxy on Linux (they trust `~/.pki/nssdb`, not the system store); the fix is to add the CA there, not to whitelist them. |
| Layout | Code in `src/` next to `docs/`; git repo at the project root. |
| Runtime | Python 3.13, not the handoff's 3.11: mitmproxy 12 needs 3.12+. The 640m weights are fetched at build time through the GitHub API asset endpoint (the release URL redirects scripts to a login page) and checksum-pinned. onnxruntime telemetry is disabled so nothing leaves the machine. |
| Docker | Docker Desktop (a VM). Ports bind to 127.0.0.1 only. Transparent mode is impractical here, so the proxy is explicit only. |
